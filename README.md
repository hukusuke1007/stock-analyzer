# 株分析シミュレーター

日本株の**買い判断とランク付け**を行い、仮想売買で試せる株分析ツール（API サーバー + ブラウザ UI）。リポジトリ名・パッケージ名は `stock-analyzer`。
売買ルール（急落リバウンド / スイング）に照らして銘柄を「買い / 打診買い / 見送り」に判定し、有望な順に並べる。

> [!WARNING]
> このツールの判定は投資助言ではありません。利用はすべて自己責任です。詳しくは[免責事項](#免責事項)を参照してください。

![チャート画面](docs/images/chart.png)

## 機能

| 機能                 | できること                                                                                                         |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 銘柄の判定           | 証券コードを指定して、売買ルールに照らした「買い / 打診買い / 見送り」と、根拠・懸念点・利確 / 損切りラインを出す |
| 全銘柄スキャン       | 東証プライム全銘柄（約1,560）を調べ、候補を判定して一覧にする                                                      |
| AI によるランク付け  | 判定済みの上位30件を AI が見比べ、順位・スコア・理由を付けて並べる                                                 |
| 売買ルールの切り替え | 急落リバウンド（大型株の急落を狙う逆張り）/ スイング（上昇トレンドの押し目買い）                                   |
| 材料のチェック       | 次回の決算発表日と直近のニュース見出しを取り、決算が近い・悪材料がある銘柄を見送りにする                           |
| チャート             | 日足・移動平均・ボリンジャーバンド・一目均衡表・出来高・RSI・RCI・MACD と、判定・利確 / 損切りラインの表示        |
| 関心銘柄             | ウォッチリストと、複数銘柄のチャートを並べて見る一覧タブ                                                           |
| 株シミュレーター     | 元金を決めて仮想売買し、利確 / 損切りラインで売ったときの損益を確かめる。チャート右上・スクリーナーの「売買」からその場で売買できる（実際には発注しない） |
| リアルタイム更新     | 取引時間中は1分ごとに株価を取り直す（約20分遅れ）                                                                  |
| 設定                 | 判定に使う AI（Codex / Jev）と Codex のモデルを画面から切り替える                                                  |
| スマホ対応           | スマホ幅では1列に積み、画面の切り替えタブを下に固定する。売買・設定は下から出るシートで開く                        |
| API                  | 上の機能を HTTP の API(`/judge`・`/screen`・`/sim` など)で使える                                                  |

| AI の使いどころ             | 使う AI                                                                                                                                                                       |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 銘柄ごとの判定（Decisions） | 既定は **Codex App Server** 経由の GPT-6 Luna（Codex CLI のログインで動く。API キー不要）。画面の設定で TypeSafe AI の **Jev**（Decision API）に切り替えられる |
| 複数銘柄のランク付け        | **Codex App Server** 経由の GPT-6 Luna。上位30件を見比べて順位・スコア・理由を付ける                                                                                          |

判定の考え方・売買ルールの中身・AI の使い分けは [DESIGN.md](DESIGN.md) にまとめている。

## 起動の仕方

### 必要なもの

| もの                    | バージョン | 用途                                                                       |
| ----------------------- | ---------- | -------------------------------------------------------------------------- |
| Node.js                 | 24 以上    | API サーバーと UI の開発サーバー                                           |
| pnpm                    | 12.8.1     | パッケージ管理（`package.json` の `packageManager` で固定）                |
| Codex CLI               | 0.160 以上 | 判定とランク付け（Codex App Server）。ChatGPT アカウントでログインしておく |
| TypeSafe AI の API キー | —          | 判定を Jev に切り替えるときだけ                                            |

Codex CLI がなくても起動する（下の「AI なしで動かす」）。

### 1. インストール

```sh
git clone <このリポジトリの URL> stock-analyzer
cd stock-analyzer
pnpm install
```

### 2. Codex にログイン

```sh
codex --version   # 0.160 以上か確認
codex login       # ChatGPT アカウントでログイン(済みなら不要)
```

### 3. Jev を使うときだけ: API キーを書く（任意）

判定の AI は既定で Codex なので、何もしなくてよい。Jev に切り替えたいときは、先に API キーを `.env` に書いておく。

```sh
cp .env.example .env
# .env の TYPESAFE_API_KEY= に https://console.typesafe.ai/keys で発行したキーを書く
```

`.env` は起動時に自動で読み込まれる。`.gitignore` で除外しているのでコミットされない。
AI の切り替えとモデルの変更は、起動後に画面の設定で行う（下の「設定」）。

### 4. 起動

```sh
pnpm dev
```

API サーバー（<http://localhost:3000>）と UI（<http://localhost:5173>）が同時に立ち上がる。ブラウザで <http://localhost:5173> を開く。
ターミナルには、AI が使えるかどうかが出る。

```text
. dev:api: http://localhost:3000
. dev:api: 判定(Decisions): Codex(Codex App Server) — 有効
. dev:api: ランク付け: Codex(gpt-6-luna) — 有効
```

UI をビルドして API サーバーから配信するときは次のとおり。<http://localhost:3000> を開く。

```sh
pnpm ui:build && pnpm start
```

### 5. 動作確認

```sh
curl -s localhost:3000/health
# {"ok":true,"decisions":{"provider":"codex","label":"Codex(Codex App Server)","available":true},"codex":true,"codexModel":"gpt-6-luna"}
```

UI の右上にも「判定: Codex / ランク: Codex」と出る。「(未接続)」が付いている方は使えていない。

### AI なしで動かす

| 状態                                                                     | 動き                                                               |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| 判定の AI を使えない（Codex CLI がない・未ログイン、Jev でキーが未設定） | 数値条件だけで判定する（`decision` は `null`）                     |
| Codex CLI がない・ログインしていない                                     | ランク付けをせず、判定順に並べる（`ranking` は `null`）            |
| AI の呼び出しが失敗した                                                  | その回は上と同じ動きにして、失敗の内容を懸念点（`concerns`）に出す |

### 環境変数

| 環境変数             | 既定         | 内容                                                                                                                     |
| -------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `TYPESAFE_API_KEY`   | なし         | Jev の API キー（設定で判定の AI を Jev にするときだけ）                                                                 |
| `CODEX_BIN`          | `codex`      | Codex CLI のパス                                                                                                         |
| `DECISIONS_EFFORT`   | `low`        | Codex での判定の推論の深さ                                                                                               |
| `RANK_EFFORT`        | `medium`     | ランク付けの推論の深さ                                                                                                   |
| `DATA_DIR`           | `./data`     | 判定結果・関心銘柄・シミュレーターの口座・設定の保存先                                                                   |
| `PORT`               | `3000`       | API サーバーのポート                                                                                                     |

### うまく動かないとき

- **`pnpm install` が `ERR_PNPM_MISSING_TARBALL_INTEGRITY` で止まる:** `pnpm-lock.yaml` の `xlsx` の integrity が消えている。`pnpm clean --lockfile && pnpm install` で作り直す
- **`ERR_PNPM_IGNORED_BUILDS`(esbuild):** `pnpm-workspace.yaml` の `allowBuilds` に esbuild があるか確認する
- **「(未接続)」のまま:** `codex --version` が 0.160 以上か、`codex login` 済みかを確認する。古い Codex だとモデルが ChatGPT アカウントで使えずに失敗することがある。Jev のときは `TYPESAFE_API_KEY` が入っているかを確認する

## 使い方（ブラウザ UI）

### よくある流れ

1. 上部で売買ルール（急落リバウンド / スイング）を選ぶ
2. 下のスクリーナーで「全銘柄スキャン」を押す。東証プライム全銘柄を判定し、上位30件を Codex がランク付けする（数分かかる）
3. 表の「順位」列で並べ、上位の銘柄をクリックする。チャートと右の「判定の詳細」に、条件ごとの判定・売り方・Codex の順位と理由・Decisions の確率が出る
4. 気になる銘柄は、ニュースを調べて右下の欄に貼り、「ニュース込みで再判定」で悪材料がないか確かめる
5. 買う候補は「関心」にチェックして関心銘柄に入れ、関心銘柄タブでまとめて見る
6. 実際に買う前に、シミュレーター タブで仮想売買して、利確 / 損切りラインでの損益を確かめる

決算をまたがないか確かめたいときは、上部の「材料」で **決算** をオンにしてから判定・スキャンする。

### 画面の各部

冒頭のスクリーンショットがチャート画面。中央がチャート、その下がスクリーナー、右がウォッチリストと判定の詳細。

アプリ名は「株分析シミュレーター」。TradingView 風の画面（Vite + [lightweight-charts](https://github.com/tradingview/lightweight-charts)）。

| 場所               | できること                                                                                                                                                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 上部バー           | 銘柄検索(銘柄名・証券コードで候補を出し、選ぶとチャートを開く。候補の ☆ で関心銘柄に登録)、売買ルールの切り替え、材料(決算・ニュース)、インジケーターの表示、AI の状態(クリックで設定を開く)、判定                                                |
| チャート           | 日足・移動平均(5 / 25 / 75 / 100)・ボリンジャーバンド・一目均衡表・出来高・RSI・RCI・MACD。判定のマーカーと利確 / 損切りのライン。右上の「売買」で売買ダイアログを開く                                                                                            |
| 左ツールバー       | 十字線 / マグネット、利確・損切りラインの表示切り替え、全体表示、スクリーンショット保存。一番下の歯車で設定を開く                                                                                                                                     |
| 右: ウォッチリスト | 銘柄の追加・削除。終値・前日比・判定。右パネルの左端で幅、ウォッチリストの下端で高さをドラッグで変えられる                                                                                                                  |
| 右: 判定の詳細     | 条件ごとの判定、売り方、Codex ランキング(順位・スコア・理由)、Decisions の確率、懸念点。ニュースを貼って「ニュース込みで再判定」                                                                                            |
| 下: スクリーナー   | 全銘柄スキャンの進捗と結果の表。Codex のランキングの要約。判定・大型株・文字列で絞り込み、列(順位・条件・R/R・買い確率など)で並べ替え。「関心」のチェックで関心銘柄に記録。「売買」で売買ダイアログを開く。「結果をクリア」で今の売買ルールの保存結果を削除 |

- 判定した結果の並びは、Codex のランキング順（ランク付けしていなければ判定順）
- スクリーナーの「順位」にマウスを載せると、Codex がその順位にした理由が出る
- `http://localhost:5173/#7203` のように URL で銘柄を指定できる

#### インジケーター

既定は、急落リバウンドが MA25・MA100・ボリンジャーバンド・一目均衡表・出来高・RCI、スイングが MA25・MA75・MA100・ボリンジャーバンド・一目均衡表・出来高・RSI・MACD。
インジケーターメニューでは、ボリンジャーバンド(中バンド・±1σ・±2σ・±3σ)と一目均衡表(転換線・基準線・先行スパン1・先行スパン2・遅行スパン・雲)を1本ずつ表示 / 非表示にできる(中バンドと±1σは最初は非表示)。
一目均衡表の雲は、先行スパンAが上なら緑、Bが上なら赤。先の雲が見えるよう、チャートの右を空けている。
「データ表示」をオンにすると、マウスカーソルの横に四本値・各指標の値・利確 / 損切りラインの一覧カードを出す。
チャート内の TradingView のロゴは出さず、帰属表示は期間ボタンの並びの右端(関心銘柄タブは下部)の「Charts by TradingView」リンクで行う(lightweight-charts のライセンスでページ内の表示が必要)。

### 関心銘柄タブ

![関心銘柄タブ: ウォッチリストの銘柄のチャートを並べた画面](docs/images/watchlist.png)

上部の「関心銘柄」タブで、ウォッチリストの銘柄のチャートを行列に並べる。

- 1行の表示数は1〜5から選ぶ。縦にスクロールして全銘柄を見る
- 見出しをドラッグして並べ替える。「並べ替え…」で判定順・前日比順・コード順に一括で並べ直すこともできる
- チャートをダブルクリック(または見出しの ↗)でチャートタブに開く
- 並び順と1行の表示数は右側のウォッチリストと共通

### シミュレーター タブ（仮想売買）

![シミュレーター タブ: 資産の概要・注文・保有株・売買履歴](docs/images/simulator.png)

元金から銘柄を買って、利確・損切りラインで売ったときの損益を見ながら売買の練習ができる。**実際には発注しない。**
関心銘柄タブの各チャートの「買う」を押すと、その銘柄を注文欄に入れて開く。

タブを移らずに売買したいときは、チャート右上・判定の詳細の見出し・スクリーナーの各行にある「売買」を押す。シミュレーターの注文欄と同じ内容(現在値・判定・株数・約定代金・利確 / 損切りラインで売ったときの損益・保有中の損益)が売買ダイアログで開き、そのまま「買う」「売る」で約定する。

| 場所             | できること                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 上部             | 元金の設定(既定 100万円)。「この元金で始め直す」で保有株と売買履歴を消してやり直す。右端に今の資産額と元金からの損益                               |
| 資産の概要       | 総資産・損益(元金比)・現金(買付余力)・保有株の評価額・含み損益・実現損益                                                                           |
| 注文             | 証券コードと株数(100株単位。「最大」で買える最大の株数)を入れて「買う」「売る」。約定代金と、今の判定の利確 / 損切りラインで売ったときの損益を出す |
| 関心銘柄から買う | ウォッチリストの銘柄ごとに現在値・判定・100株の約定代金と損益の見込み。「100株買う」でその場で買う。行をクリックすると注文欄に入れる               |
| 保有株           | 取得単価・現在値・評価額・含み損益、利確 / 損切りラインとそこで売ったときの損益、状態(利確ライン到達 / 損切りライン到達)。一部売却もできる         |
| 売買履歴         | 日時・売買・株数・約定単価・約定代金・実現損益                                                                                                     |

- 約定単価は注文のたびに取る Yahoo Finance の最新の日足の終値(取引時間中は現在値、東証は約20分遅れ)
- 手数料・税金は含めない。同じ銘柄を買い増すと取得単価は平均し、利確 / 損切りラインはそのときの判定に置き換える

### 材料（決算・ニュース）

上部の「材料」で **決算** と **ニュース** をオン / オフできる。オンにしたものだけ、判定とスキャンで調べる。

- **決算:** 次回の決算発表日を JPX(なければ Yahoo の推定日)から取る。発表まで5営業日以内なら「見送り」。推定日には「(推定)」「?」を付けて出す
- **ニュース:** 直近7日の見出しを Google ニュースから取り、悪材料なら「見送り」。スキャンでオンにすると候補の数だけ取るので、1分ほど延びる

判定での扱いの詳細は [DESIGN.md](DESIGN.md#テクニカル以外の材料決算ニュースと判定の関係) を参照。Google ニュースの RSS は個人の閲覧用途に限って使える。

### リアルタイム更新

取引時間中(平日 9:00〜15:45)は1分ごとに日足を取り直し、当日の足・インジケーター・価格表示を差し替える。
上部の「● ライブ」を押すと、時間外でもすぐに取り直す。
判定(利確 / 損切りライン)は自動では出し直さないので、必要なら「判定」を押す。

### 設定

左ツールバーの一番下の歯車(または上部バーの AI の状態)を押すと、設定ダイアログが開く。

| 項目                      | 内容                                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------------ |
| 判定(Decisions)に使う AI | Codex(Codex App Server、既定)/ Jev(TypeSafe AI)。使えない方には理由(未ログイン・キー未設定)を出す |
| Codex のモデル            | 判定(Codex を選んだとき)とランク付けに使うモデル。既定は `gpt-6-luna`。ChatGPT アカウントで使えるものが並ぶ |
| このアプリについて        | バージョン・ライセンス・作者(hobbydevelop)・X のアカウント                                            |

「保存」で `data/settings.json` に保存し、次の判定から使う。ランク付けは、判定の AI をどちらにしても Codex で行う。

### 保存されるもの

| 内容                                                                                                        | 保存先                                  |
| ----------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| 銘柄を指定した判定の結果(売買ルール・銘柄ごとに最新だけ)                                                    | `data/judgments/<strategy>/<code>.json` |
| 全銘柄スキャンの結果(実行ごとに1ファイル。ランキングを含む)                                                 | `data/screens/<strategy>/<日時>.json`   |
| 関心銘柄の並び順・1行の表示数                                                                               | `data/watchlist.json`                   |
| シミュレーターの口座(元金・現金・保有株・売買履歴)                                                          | `data/simulator.json`                   |
| 設定(判定の AI・Codex のモデル)                                                                              | `data/settings.json`                    |
| 売買ルールの選択・材料のオン / オフ・期間・タブ・インジケーターと線ごとの表示・データ表示・ニュースの下書き | ブラウザの localStorage                 |

`data/` は `.gitignore` で除外している。UI は起動時に保存済みの結果を読み込み、前の営業日の終値のものなら銘柄を開いたときに判定し直す。

## 使い方（API）

`strategy` は `rebound`（省略時）または `swing`。それ以外は 400 を返す。

### 東証プライム全銘柄を調べる（`GET /screen`）

時間がかかる（急落リバウンドで候補728件のとき約4分。2026-10-03 計測）ので、進捗を SSE（Server-Sent Events）で返す。`&earnings=1` `&news=1` で材料を足す。

```sh
curl -sN 'localhost:3000/screen?strategy=swing' | jq -R --unbuffered -r '
  select(startswith("data: ")) | .[6:] | fromjson
  | if .phase then "\(.phase) \(.done)/\(.total)"
    else {summary, ranking, top: [.results[:10][] | {code, name, verdict, satisfied, ranking}]} end'
```

```text
listing 1/1
analyze 78/1557
…
judge 626/626
rank 0/1
rank 1/1
{ "summary": { … }, "ranking": { "model": "…", "summary": "…", "ranked": 30, "error": null }, "top": [ … ] }
```

| イベント   | data                                                                               | 送るタイミング               |
| ---------- | ---------------------------------------------------------------------------------- | ---------------------------- |
| `progress` | `{"phase","done","total"}`。phase は `listing` / `analyze` / `judge` / `rank`      | 各フェーズの 5% 刻みと完了時 |
| `result`   | 全結果（`disclaimer` / `strategy` / `summary` / `ranking` / `results` / `errors`） | 最後に1回                    |
| `error`    | `{"error"}`                                                                        | 銘柄一覧の取得失敗など       |

`-N` を付けないと curl が出力をためてしまい、進捗がまとめて表示される。

- 明らかに見送りの銘柄は結果に含めない（基準は [DESIGN.md](DESIGN.md#銘柄の選び方) の各ルール）
- `summary` に銘柄数と判定ごとの件数、`errors` に取得できなかった銘柄が入る
- 各結果には JPX の `sector`（33業種）と `scale`（規模区分）が付く。大型株に絞るなら `scale` が `TOPIX Core30` / `TOPIX Large70` のものを見る

### 銘柄を指定して調べる（`POST /judge`）

```sh
curl -s -X POST localhost:3000/judge \
  -H 'Content-Type: application/json' \
  -d '{"strategy":"swing","codes":["7203","6758","8306","9432","6857"]}' \
  | jq '{ranking, results: [.results[] | {rank: .ranking.rank, code, verdict, satisfied, reason: .ranking.reason}]}'
```

2銘柄以上なら Codex がランク付けし、その順で返す（判定とランク付けを合わせて、5銘柄で約35秒）。

材料を調べたら、`news` に銘柄ごとのニュース本文を入れる。決算・ニュースを自動で取るなら `options` を付ける。

```sh
curl -s -X POST localhost:3000/judge \
  -H 'Content-Type: application/json' \
  -d '{"codes":["7203"],"news":{"7203":"特に目立ったニュースなし。米国市場の下落につられた"},"options":{"earnings":true}}'
```

### レスポンスの主な項目

| 項目                                 | 内容                                                                                                |
| ------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `verdict` / `reason`                 | 判定（買い / 打診買い / 見送り）と、その理由                                                        |
| `rationale`                          | 買いの根拠。満たした条件を「条件: 現在値(基準)」の形で並べる                                        |
| `concerns`                           | 懸念点。満たしていない条件、ニュースが未確認であること、AI の失敗                                   |
| `sellPlan.takeProfit`                | 利確の価格・現在値からの変化率（`pct`）・売るタイミング（`when`）                                   |
| `sellPlan.stopLoss`                  | 損切りの価格・変化率・条件                                                                          |
| `sellPlan.signals`                   | 保有中に見る、売るタイミングの指標（現在値つき）                                                    |
| `sellPlan.riskReward`                | 第1目標までの値幅 ÷ 損切り幅                                                                        |
| `checks` / `technicals` / `decision` | 条件ごとの判定、テクニカル指標、Decisions の答え（中身はルールによって異なる）                      |
| `ranking`                            | Codex App Server のランキング（`rank` / `score` / `reason`）。2銘柄以上を判定したときの上位30件だけ |

トップレベルの `ranking` には、Codex のモデル名・上位の傾向の要約（`summary`）・ランク付けした件数（`ranked`）・失敗したときのエラー（`error`）が入る。

### エンドポイント一覧

| メソッド | パス                     | 内容                                                                                                                                           |
| -------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET`    | `/health`                | 起動確認。`decisions`(判定の AI と使えるか)と `codex`(ランク付けに使えるか)                                                                    |
| `GET`    | `/settings`              | 設定(`settings`)、選択肢(判定の AI・Codex のモデル)、アプリの情報(`app`)                                                                                    |
| `PUT`    | `/settings`              | 設定を変える。body は `{"decisionsProvider":"codex"|"jev","codexModel":"gpt-6-luna"}`(省略した項目はそのまま)                                                 |
| `GET`    | `/strategies`            | 売買ルールの一覧(`id` / `label`)                                                                                                               |
| `GET`    | `/search?q=<文字列>`     | 銘柄検索。証券コードの前方一致・銘柄名の部分一致(ひらがな・カタカナ・半角カナを区別しない)。プライム・スタンダード・グロースから最大12件       |
| `GET`    | `/bars/:code`            | 日足1年分(`bars`: date / open / high / low / close / volume)                                                                                   |
| `GET`    | `/screen?strategy=<id>`  | 東証プライム全銘柄を調べる（SSE）。`&earnings=1` `&news=1` で材料を足す                                                                        |
| `POST`   | `/judge`                 | 指定した銘柄を調べる。body は `{"strategy","codes","news","options"}`。`options` は `{"earnings":true,"news":true}`                            |
| `GET`    | `/results?strategy=<id>` | 保存済みの判定結果(`judgments`: 銘柄ごとの最新、`screen`: 最新のスクリーニング)                                                                |
| `DELETE` | `/results?strategy=<id>` | 保存済みの判定結果を消す(`strategy` は必須)                                                                                                    |
| `GET`    | `/watchlist`             | 関心銘柄(`codes` / `columns`)。未保存なら `codes` は `null`                                                                                    |
| `PUT`    | `/watchlist`             | 関心銘柄を保存。body は `{"codes":["7203"],"columns":3}`(`columns` は1〜5)                                                                     |
| `GET`    | `/sim`                   | シミュレーターの口座。保有株の現在値・含み損益・利確 / 損切りラインで売ったときの損益(`pnl`)と、`summary`(総資産・損益など)                    |
| `POST`   | `/sim/reset`             | 元金を指定して始め直す。body は `{"initialCash":1000000}`(省略時は100万円)                                                                     |
| `POST`   | `/sim/orders`            | 仮想売買。body は `{"code":"7203","side":"buy","shares":100,"plan":{…}}`。`shares` は100株単位。`plan` は買ったときの判定の利確 / 損切りライン |

## 参考文献

判定ルールと指標の根拠にした文献・資料。ルールの中身は [DESIGN.md](DESIGN.md#銘柄の選び方) を参照。

### 急落リバウンド(逆張り)の考え方

- W. F. M. De Bondt, R. Thaler, "Does the Stock Market Overreact?", *The Journal of Finance*, 40(3), 793–805, 1985. [doi:10.1111/j.1540-6261.1985.tb05004.x](https://doi.org/10.1111/j.1540-6261.1985.tb05004.x) — 投資家が劇的なニュースに過剰反応し、売られすぎた銘柄がのちに戻る(過剰反応仮説)
- N. Jegadeesh, "Evidence of Predictable Behavior of Security Returns", *The Journal of Finance*, 45(3), 881–898, 1990. [doi:10.1111/j.1540-6261.1990.tb05110.x](https://doi.org/10.1111/j.1540-6261.1990.tb05110.x) — 短期の値動きが反転しやすい(短期リバーサル)

### スイング(順張り・押し目買い)の考え方

- N. Jegadeesh, S. Titman, "Returns to Buying Winners and Selling Losers: Implications for Stock Market Efficiency", *The Journal of Finance*, 48(1), 65–91, 1993. [doi:10.1111/j.1540-6261.1993.tb04702.x](https://doi.org/10.1111/j.1540-6261.1993.tb04702.x) — 上昇してきた銘柄はその後も上がりやすい(モメンタム)
- W. Brock, J. Lakonishok, B. LeBaron, "Simple Technical Trading Rules and the Stochastic Properties of Stock Returns", *The Journal of Finance*, 47(5), 1731–1764, 1992. [doi:10.1111/j.1540-6261.1992.tb04681.x](https://doi.org/10.1111/j.1540-6261.1992.tb04681.x) — 移動平均を使った売買ルールの検証
- [20 Moving Average Pullback Strategy](https://www.tradingsim.com/blog/20-moving-average-pullback)(TradingSim) — 上向きの移動平均までの押し目で、反転を確認して買う。損切り・時間切れの置き方
- [株のスイングトレードで勝つための10の必須ルール](https://crexgroup.com/ja/sec/stock-investment/swing-trade-rules/)(証券会社比較なび) — 損切り・利確目標を先に決める、順張りを基本にする
